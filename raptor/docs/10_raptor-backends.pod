=TITLE raptor-backends - --go, --moar, --wasm

=head1 NAME

raptor-backends - how each backend runs a program

=head1 --go (default)

Tree-walk interpreter in F<runtime/eval.go>. This is the B<full
language>: TAP, FFI, structs, SQLite, junctions, PodLit, RaptorHP
helpers, concurrency, the lot. C<raptor test t/> and the examples
run here.

=head1 --moar

Emits CompUnit v7 and executes it on C<moar.dll> (same opcode family
as the Tcl frontend in F<../moarvm-go>). There is B<no Go fallback>.
If the compiler cannot emit valid bytecode, it errors.

Native today: scalars, arrays (C<@a[$i]>, C<elems>/C<push>/C<pop>/
C<shift>, C<xx>), hashes (C<%h{"k"}>, C<exists>/C<delete>), C<for>
(including postfix), C<given>/C<when>, C<~~>, C<goto LABEL>, C<enum>,
named subs and closures, UFCS, C<last>/C<next>/C<redo>, C<subset>/C<multi>, C<struct> fields as
hashes, junctions C<any>/C<all>, eager C<gather>/C<take>, substring
regex via C<index>, C<use> (compile-time include), C<package>,
NativeCall (C<nativecallbuild>/C<invoke>), C<system>/C<qx>,
C<slurp>/C<open>/C<spurt>, TAP including C<is_deeply> and C<like>.

Not compiled (hard error): SQLite, sockets/HTTP, TUI, Perl 5 C<use>,
and anything else the compiler cannot emit as CompUnit v7.

    raptor --moar -e 'say 40 + 2;'     # 42
    raptor --moar test t/01_operators.t

=head1 --wasm

Builds F<web/raptor.wasm>. Prefers TinyGo when C<tinygo> is on PATH;
C<--wasm-compiler=go|tinygo> forces a toolchain. Writes
C<raptor_bridge.js> and C<wasm_exec.js> next to the C<.wasm>.

    raptor --wasm --wasm-compiler=go -o web/raptor.wasm
    raptor serve --port 8080

The tour HTTP and WebGPU lessons are disabled. Desktop C<--wasm> as an
I<execution> backend still evaluates source with the Go interpreter
after setting C<$*WASM>.
